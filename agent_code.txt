Understanding Agent Code and Development
Agent code in Cosmitude Bridge is the technical foundation that enables automated operations within forums. This guide provides a comprehensive understanding of how agent code is structured, how it operates, and how to safely customize it for your specific automation needs.
All agent code is written in Python and follows a standardized structure that handles authentication, event monitoring, and response processing.
Key Concept
: Agent code provides the programming logic that transforms visual configurations into executable automation. Understanding the code structure helps you customize and extend agent capabilities safely.
Important
: When customizing agent code, always test thoroughly in a development environment before deploying to production. Modifications outside the designated custom areas may break agent functionality.
Agent Code Architecture
Python-Based Implementation
Core Requirements:
Agents are programmed exclusively in Python (.py files)
Code can be downloaded and run locally on your systems
HTTPS connection to Bridge forums for secure communication
Event-driven architecture for responsive automation
Deployment Model:
Local execution with remote forum connectivity
Continuous operation through monitoring loops
Real-time event processing and response generation
Secure session management and authentication

Key Code Components Explained
Main Execution Functions
go()
 - Main execution function
Purpose
: Initiates agent operation and establishes continuous monitoring
Loop
: Calls 
clientSync()
 every 10 seconds to check for new events
Error Handling
: Catches and prints any exceptions that occur
Timing
: 10-second intervals provide real-time responsiveness without overloading servers
login()
 - Authentication system
Purpose
: Authenticates agent with Bridge servers using unique credentials
Session Management
: Retrieves and stores session ID for subsequent API calls
Security
: Uses unique user ID and forum-specific authentication
Password
: Must be replaced with actual bot password before running
getForumDetails()
 - Configuration retrieval
Purpose
: Downloads current forum configuration and template data
Local Storage
: Saves configuration to text file for reference
Updates
: Automatically retrieves latest forum structure
File Format
: JSON format for easy parsing and reference
clientSync()
 - Event monitoring
Purpose
: Polls Bridge servers for new events and data
Event Types
: Processes bridges, whispers, and template updates
Data Structure
: Receives admin-level sync data from Bridge
Custom Area
: Contains the designated area for your custom logic

Safe Implementation Example:
Safe Customization Guidelines
✅ Safe Practices:
Add simple if/elif conditions for different flow names
Use basic string responses for bridge and whisper data
Keep logic simple and straightforward
Test with actual flow names from your forum
Use print statements for debugging
❌ Avoid These Risky Practices:
Modifying the core authentication or session management code
Adding complex external API calls without testing
Modifying global variables outside the custom section
Supported Agent Operations
The Five Core Operations
sendBridge(bridgeData, flowName, replyData)
Purpose
: Send public communication visible to all forum participants
Usage
: General announcements, data sharing, status updates
Example
: 
sendBridge(bridgeData, 'StatusUpdate', 'Process completed successfully')
sendWhisper(bridgeData, flowName, replyData)
Purpose
: Send private communication visible only to specific recipients
Usage
: Confidential messaging, sensitive alerts, personal notifications
Example
: 
sendWhisper(bridgeData, 'PrivateAlert', 'Your request has been processed')
generateReport(bridgeData, flowName)
Purpose
: Generate and send automated reports
Usage
: Scheduled reports, data summaries, analytics
Example
: 
generateReport(bridgeData, 'WeeklySummary')
sendBridgeToSet(bridgeData, flowName, replyData, setName)
Purpose
: Send bridge communication to specific user groups
Usage
: Team notifications, department updates, role-based messaging
Example
: 
sendBridgeToSet(bridgeData, 'TeamAlert', 'Meeting reminder', 'SalesTeam')
sendSpecific(bridgeData, flowName)
Purpose
: Send targeted communication to specific individuals
Usage
: Personal alerts, escalation notifications, individual responses
Example
: 
sendSpecific(bridgeData, 'PersonalAlert')

Performance Considerations
Efficient Custom Logic:
Keep conditional logic simple and fast
Avoid complex calculations in the sync loop
Use appropriate data types and avoid unnecessary conversions
Monitor agent resource usage
Network Reliability:
The 10-second sync interval is optimized for Bridge servers
Don't modify timeout values without testing
Handle network connectivity issues gracefully
Monitor agent uptime and availability
Common Issues and Solutions
Typical Problems
Authentication Failures:
Check bot password is correct
Verify forum ID matches target forum
Ensure bot user exists and has proper permissions
Flow Name Mismatches:
Use exact flow names from your forum
Check for typos in flow name strings
Verify flows exist in both admin and user sections as appropriate
Response Not Appearing:
Confirm target flow exists and is accessible
Check that response data is properly formatted
Verify bot has permissions to send to target flow

def getForumDetails():


    try:


        tempJson = {


        "MACAddress": '<MAC Address>',


        "ForumID":forumID,


        "SessionID":Sessionid,


        "ServerID":'<ServerID>'


        }


        headers = {'Content-Type': 'application/json'}


        variab =json.dumps(tempJson)


        response = requests.post('<URL>' + 'getRequestedForumDetails', data=variab,headers=headers, timeout=600)


        if response.status_code == 200:


            responseStr = str(response.text)


            respJson = json.loads(responseStr)


            errorCode = respJson['ErrorCode']


            if errorCode == 1172:


                errorMsg = respJson['ErrorMessage']


                forumDetails = errorMsg['ForumDataArray']


                for singleForum in forumDetails:


                    singleForumDetails = singleForum[forumID]


                    saveForumDetails = singleForumDetails['NewForumJsonData']


                    with open('SalesDataTool_SalesDataTool_Admin.txt', 'w') as f:


                        json.dump(saveForumDetails, f)


    except Exception as e:


        print (e)


        return e
